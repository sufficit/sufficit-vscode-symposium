# Activity: HTTP 503 recovery and maintenance-page containment

## Objective

Ensure provider `HTTP 503` failures enter the existing automatic recovery policy and prevent a provider maintenance HTML page from being rendered as a large chat/system payload or sent back to the agent during manual Retry.

## Starting state

- Release `2026.903.5` already contained bounded automatic recovery for explicitly transient errors.
- The classifier recognized several capacity phrases, but did not recognize every transient HTTP status when the status text was abbreviated.
- The error presentation kept the complete provider payload as technical detail. A gateway maintenance page therefore produced a very large HTML block in the error card.
- The Retry hand-off already used `conciseRetryReason` for the agent continuity prompt, but the webview passed the raw error message into that hand-off.

## Changes

- Added explicit retry classification for HTTP `408`, `425`, `429`, `500`, `502`, `503` and `504`.
- Added bounded provider-error presentation (512 characters maximum) that removes scripts, styles and HTML tags while retaining the HTTP status and page title when available.
- Changed manual Retry to pass the compact technical detail instead of the raw provider payload.
- Marked Retry and Edit controls as non-submit buttons.
- Added regression coverage for abbreviated transient statuses, 503 maintenance HTML, compact technical detail, manual retry hand-off, automatic exhaustion and UI-only recovery state.

## Decisions and constraints

- Reused `TransientRetryController`; no second retry loop was introduced.
- Automatic retry remains bounded by the configured limit and remains UI-only, so it never creates a new user row or injects the recovery card into the agent transcript.
- Session-limit errors remain manual until their provider reset time.
- Preserved unrelated user changes in `.gitignore` and `README.md`.

## Validation

- `npm run compile:test` — passed.
- Focused recovery/presentation/webview tests — 46 passed, 0 failed.
- `npm run verify` — passed: release guardrail, formatting, lint, TypeScript, webview typecheck, full tests/coverage, webview/config/size/engineering/architecture checks, and compile.
- Complexity output contains only the repository's existing non-blocking inventory warnings.

## Delivery

- Source changes are ready for release `2026.903.6` with recovery feature version `1.3.3`.
- The existing VSIX/release `2026.903.5` remains untouched until this change is versioned and published.

## Known limitation

The external provider can remain unavailable after all bounded attempts. In that case the UI must show the exhausted state and expose manual Retry; this change ensures that state is concise and safe even when the provider returns a full HTML maintenance page.
