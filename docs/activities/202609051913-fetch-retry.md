# Atividade — retry automático de `fetch failed`

Data: 2026-09-05 19:13 (America/Sao_Paulo)

Release planejada: `2026.903.5`; feature `symposium.recovery` `1.3.2`.

## Sintoma

No adaptador Claude, uma falha transitória retornada pelo CLI como:

```text
result.is_error = true
result = "fetch failed"
```

era exibida diretamente como erro terminal. O cartão informava que a recuperação automática estava indisponível ou esgotada, mas não aparecia tentativa nem contagem regressiva.

## Causa

`ClaudeEventParser.handleResult()` só adicionava `retryable: true` para erros associados a limite de sessão com horário de reset. Erros transitórios comuns não recebiam a classificação; o controlador de retry exige essa marca para evitar reexecuções inseguras.

## Correção

- Classificação dos erros `result.is_error` do Claude com `isTransientErrorMessage()`.
- Preservação da regra de limite de sessão: continua `retryable`, mas com `automaticRetry: false` e `retryAt`, portanto o botão só fica disponível no reset.
- A mensagem reenviada pelo retry continua sem nova linha de usuário e com metadados UI-only de recuperação.
