# Release v2026.921.4 — Jev context pruning

## Objetivo

Publicar o jev (poda de contexto entre turnos) no adaptador Sufficit AI como
`v2026.921.4`, com entrega idêntica no GitHub Releases, Visual Studio
Marketplace e Open VSX.

## Estado inicial

- `develop`/`main`/`origin` estavam em `a67186b`, correspondente à release
  anterior `v2026.921.2`.
- O trabalho do jev estava pronto na branch `feature/jev-compaction`
  (módulo `src/adapters/openai/jev/`, integração mínima, 12 testes novos,
  suíte completa 793/793), ainda sem commit.
- A política CalVer para 2026-09-21 determinou a primeira tentativa
  `2026.921.3`.

## Entrega

- Commit de feature
  `152ac83` (`feat(jev): prune obsolete tool results between turns`, 16
  arquivos, +1642), integrado ao `develop` por fast-forward.
- Primeira tentativa `v2026.921.3` (`b7edd1b`): verify completo verde, mas o
  workflow de publicação (run `35660000574`) falhou em *Validate VSIX
  contents* — o bundle host cresceu para 877.338 bytes contra o teto de
  868.352 bytes (848 KiB) do guardrail.
- Teto do bundle host reajustado para 864 KiB em `scripts/check-vsix.mjs`
  (`e0edc84`, `build: budget jev host bundle`), com comentário registrando a
  causa; validado localmente com VSIX de 525.871 bytes.
- Versão `2026.921.4` sincronizada em `package.json`, `package-lock.json` e
  `VERSION.md`; commit de release `822eb05` publicado em `develop`.
- `main` promovida por fast-forward ao mesmo commit.
- Tag anotada `v2026.921.4` criada a partir de `develop` e publicada no commit
  exato da release.
- Workflow `Publish VS Code Extension` run `35660515477` concluído com sucesso
  em 2min10s.
- A tag `v2026.921.3` permanece no histórico apontando para `b7edd1b`, com o
  run de publicação correspondente documentado como falha do guardrail de
  tamanho.
